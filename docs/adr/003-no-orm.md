# ADR-003 — Repository עם SQL מפורש, ללא ORM

**סטטוס:** מוצע · 2026-09-09

## הקשר

ברירת המחדל ב-Flask היא SQLAlchemy. עבור CRM זו לא בהכרח הבחירה הנכונה.

## נימוק

1. **שאילתות CRM הן analytics-heavy** — משפך המרות, ביצועי נציגים, תחזית תזרים.
   אלה שאילתות עם window functions ו-CTEs שנכתבות בקלות ב-SQL ובכאב ב-ORM.
2. **N+1 הוא כשל ברירת המחדל של ORM** — טיימליין עם 50 אירועים ומידע על מבצע כל אירוע
   הופך ל-51 שאילתות בלי ש-ORM יתריע.
3. **הזרקת ה-RLS** דורשת שליטה מפורשת בתחילת הטרנזקציה — אפשרי ב-SQLAlchemy אך נוח
   יותר עם `psycopg` ישיר.
4. **תוכנית הביצוע גלויה** — `EXPLAIN ANALYZE` על השאילתה שבקוד, לא על מה ש-ORM ייצר.

## מה מוותרים עליו

- מיפוי אוטומטי לאובייקטים → נכתב ידנית (row → dataclass) ב-repository
- מיגרציות מ-models → כותבים SQL. מקובל: הסכימה כאן מתוכננת מראש ולא נגזרת מקוד.
- הגנה אוטומטית מ-injection → מוחלפת בכלל נוקשה: פרמטרים בלבד, נאכף ב-`bandit`

## החלטה

`psycopg 3` + `psycopg_pool`, שכבת repository עם SQL מפורש, ומיפוי לתוך dataclasses.
כל SQL חי בקבצי `repository.py` בלבד — SQL מחוץ להם נכשל ב-lint.
