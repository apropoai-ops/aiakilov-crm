# ADR-002 — Frontend ללא Framework

**סטטוס:** מוצע · 2026-09-09

## הקשר

ה-stack שהוגדר הוא HTML5 + CSS3 + JavaScript ES2025 — ללא framework.
CRM הוא היישום שבו היעדר framework מורגש הכי חזק: טפסים מורכבים, טבלאות גדולות,
מצב משותף בין מסכים.

## מה זה עולה

ארבע יכולות שיש לקחת בחשבון שנבנה בעצמנו:

| יכולת | היקף משוער | סיכון |
|---|---|---|
| ריאקטיביות (signals) | ~120 שורות | דליפות זיכרון אם effects לא מנוקים |
| Router | ~150 שורות | נמוך |
| בסיס קומפוננטה | ~80 שורות | ניהול מחזור חיים |
| רשימה וירטואלית | ~200 שורות | הגבוה מבין הארבעה |

סה"כ ~550 שורות תשתית שצריכות להיות **מכוסות בבדיקות ברמה גבוהה יותר** מקוד המוצר,
כי כל השאר יושב עליהן.

## החלטה

ממשיכים ללא framework, בתנאי שהתשתית הזו נבנית ב-M2 כמודול נפרד, נבדק, וקפוא —
לא מתפתחת תוך כדי בניית מסכים.

## מה כן נשתמש בו

ספריות ממוקדות ליכולת אחת, לא frameworks:
- `@floating-ui/dom` — מיקום dropdowns/tooltips (חישוב collision נכון הוא קשה מהצפוי)
- ספריית תרשימים קלה לדוחות

## תנאי לבחינה מחדש

אם ב-M4 (לידים) קוד ניהול ה-state של הטפסים עובר ~800 שורות או שמופיעים באגי סנכרון
חוזרים — נעצור ונשקול Preact (3KB, JSX אופציונלי). התנאי מוגדר מראש כדי שההחלטה
תהיה מבוססת-ראיות ולא תחושה.
